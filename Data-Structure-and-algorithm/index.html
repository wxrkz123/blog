数据结构与算法入门：内存、复杂度与常见数据结构

这是我学习数据结构时的笔记，侧重于“每种数据结构在内存里是什么样子、各种操作的时间复杂度为什么是这样”。配套的代码在另一篇《用 C 语言实现常用数据结构》里：本文讲原理，那一篇用 C 语言从零实现链表、动态数组、哈希表、栈、队列、图和二叉树。建议两篇对照着读。

什么是数据结构

数据结构（data structure）是在计算机中存储和组织数据的方式。

  • 数据：QQ 号、微信 ID、商品价格、一篇文章……
  • 存储：数据以什么形式放在内存里，比如数组、链表、树、图；
  • 组织：怎样对数据进行增、删、改、查（常说的 CRUD）。

算法是解决问题的步骤。数据结构和算法密不可分：同样是“查找”，在数组、链表、哈希表、二叉搜索树上的做法和效率完全不同。选对数据结构，往往比优化算法的细节更重要。

教材中常说的线性表（linear list），指元素排成一条线、每个元素最多有一个前驱和一个后继的结构。它有两种最常见的实现：用连续内存的数组，和用指针串起来的链表。

数据在内存中的样子

可以把内存想象成一排编了号的格子，每个格子存放 1 个字节，格子的编号就是地址。

一个占多个字节的数据，必须放在连续的格子里。比如 C 语言的 int 通常占 4 个字节，存放一个 int 需要 4 个相邻的格子；一个有 4 个 int 元素的数组需要 16 个相邻的格子。如果 1 号格子已经被占用，就只能从 2 号开始放。

生活中的类比：住院部里，几个病人要求住在连续编号的病房里。如果中间某间已经有人，就只能整体换到另一段空着的病房。

int 的取值范围

int 的大小由编译器和平台决定。在今天常见的平台上（包括绝大多数 64 位系统），C 语言的 int 都是 4 个字节，即 32 位：

  • 有符号 int： 到 ，即 −2147483648 到 2147483647（最高位用作符号位，负数用补码表示）；
  • 无符号 unsigned int： 到 ，即 0 到 4294967295。

32 个二进制位一共有 种组合，所以能表示 个不同的数。需要确定大小的整数时，C 语言可以用 <stdint.h> 中的 int32_t、int64_t。

Python 的 int 则没有上限，数字有多大，它就占用多少内存（Python 系列第 02 篇有详细介绍）。

复杂度分析

同一个问题有多种解法，怎样比较它们的好坏？直接测运行时间不太可靠，因为它和机器的性能、数据的规模都有关系。复杂度分析只关心一件事：当数据规模 变大时，所需的时间（或空间）增长得有多快。

打个比方：从 a、b、c 三个地方去市中心，路程各不相同，交通工具也不同（飞机、拖拉机、汽车），谁先到达取决于两者。比较算法时，我们假设所有人用同样的交通工具（同样的机器），只比较“路程”随问题规模增长的速度。

  • 时间复杂度：运行时间随 增长的趋势；
  • 空间复杂度：额外占用的内存随 增长的趋势。

链表

单链表

链表的元素（节点）不需要连续存放。每个节点除了存放数据，还存放下一个节点的地址（指针）。就像一个寻宝游戏：每个地点除了宝物，还有一张写着下一个地点的纸条。

链表的第一个节点叫头节点，最后一个节点的指针为空（NULL）。

操作 复杂度 原因
按位置或按值查找 只能从头节点开始，顺着指针一个个找
在头部插入、删除 只需修改头指针
在已知节点之后插入、删除 只需修改几个指针，不用移动其他元素
在任意位置插入、删除 先要花 找到位置
在尾部插入 ，保存尾指针时 不保存尾指针时要先走到末尾

和数组相比，链表放弃了 的随机访问，换来了不必移动元素的插入和删除，也不需要一整块连续内存。

双向链表与循环链表

双向链表的每个节点有三部分：前驱指针 prev、数据、后继指针 next，可以双向遍历。如果同时保存头指针和尾指针，在两端插入、删除都是 ；已知某个节点时，删除它也是 （不需要再去找它的前一个节点）。

循环链表：单链表的尾节点指向头节点；双向循环链表还让头节点的 prev 指向尾节点。复杂度与对应的普通链表相同。

生活中的例子：单链表像按到达顺序登记的报名表；双向链表像浏览器的“后退”和“前进”。

哈希表

哈希函数

哈希函数（散列函数）把任意长度的输入映射成一个固定长度的值（哈希值）。好的哈希函数计算快，输出分布均匀，输入稍有变化，输出就完全不同。

不同的输入得到相同的哈希值，叫哈希碰撞。输出的长度是固定的，而输入有无穷多种，碰撞不可避免，只能尽量减少。

用于密码学的单向哈希函数（如 SHA-256）还要求：从哈希值无法反推出输入，也很难人为构造出碰撞。注意哈希不是加密：加密可以用密钥解密还原，哈希不能还原。它的应用包括：

  • 网盘“秒传”：上传前先计算文件的哈希值，如果服务器上已经有相同哈希值的文件，就不用真正上传，直接引用已有的文件；
  • 校验下载文件：软件官网会公布安装包的 SHA-256 值，下载后自己算一遍，一致就说明文件没有损坏或被篡改；
  • 保存密码：网站只保存密码的哈希值（加上随机的“盐”），即使数据库泄露，也不能直接得到密码。

哈希表的原理

哈希表（hash table，也叫 hash map、散列表）存放键值对 <key, value>：用哈希函数把 key 换算成数组的一个下标，把 value 放在那个位置。查找时再算一次哈希值，就能直接找到位置。

两个 key 算出同一个下标时（碰撞），常见的处理方法是拉链法：数组的每个位置存放一个链表，碰撞的键值对都挂在同一个链表上。另一种方法是开放寻址：位置被占了，就按某种规则去找下一个空位。

操作 平均 最坏
查找、插入、删除 （所有键都碰撞到同一个位置）

元素越来越多时，碰撞会变得频繁。通常在元素个数超过数组长度的一定比例（叫负载因子，比如 0.75）时，把数组扩大一倍并重新计算所有元素的位置。Python 的 dict、Java 的 HashMap、JavaScript 的 Map 都是哈希表。

栈

栈（stack）只允许在一端（栈顶）放入和取出元素，后进先出（LIFO）。就像餐馆里叠放的盘子：洗好的盘子放在最上面，服务员也从最上面拿。

操作 复杂度
入栈 push、出栈 pop
查看栈顶 peek
查找栈中的任意元素

用途：编辑器的撤销、浏览器的后退、函数调用（每次调用函数，都把它的局部变量压入“调用栈”）、括号匹配、表达式求值。

注意：数据结构中的“栈”和内存管理中的“堆”“栈”是不同的概念。数据结构的“堆”（heap）是一种树（见后文），中文里常说的“堆栈”一般就是指栈。

队列

队列（queue）在一端（队尾）加入元素，在另一端（队头）取出元素，先进先出（FIFO）。就像排队取票：先来的人先办理。

实现方式 入队 出队 说明
链表（保存头、尾指针） 在尾部插入，在头部删除
普通数组 出队后，后面的元素都要往前移
循环数组 用两个下标记录队头和队尾，到达数组末尾时绕回开头，不移动元素

所以队列的复杂度主要取决于实现方式，而不是元素的位置。用途：网络数据包的缓冲、操作系统的任务调度、打印队列、广度优先搜索。

树

树的术语

树表示层级关系，最直观的例子是家谱。

术语 含义 家谱中的类比
节点 树中的每个元素 家谱中的每个人
根节点 最顶端的节点，没有父节点 最早的祖先
父节点、子节点 直接相连的上下两个节点 父亲和孩子
兄弟节点 有同一个父节点的节点 兄弟姐妹
叶子节点 没有子节点的节点 还没有后代的人
子树 某个节点及其所有后代 某个人和他的所有后代
深度 从根节点到该节点的边数 你是第几代
高度 从该节点到最远的叶子节点的边数；树的高度就是根节点的高度 你下面还有几代人
层 深度相同的节点 同一辈人

树的应用：公司组织架构、文件系统的目录、HTML 文档的结构（DOM 树）、编译器的语法树、数据库索引（B+ 树）、决策树、软件的多级菜单。

常见的二叉树

二叉树：每个节点最多有两个子节点（左子节点和右子节点）。几种特殊的二叉树（中英文术语的对应关系在不同教材中不统一，这里以英文为准）：

完美二叉树（perfect binary tree）：所有内部节点都有两个子节点，所有叶子节点都在同一层。高度为 的完美二叉树有 个节点。国内很多教材把它叫做“满二叉树”。

完全二叉树（complete binary tree）：除了最后一层，每一层都是满的；最后一层的节点都靠左排列。完全二叉树可以用数组紧凑地存储（下标为 的节点，子节点的下标是 和 ），堆就是这样实现的。

平衡二叉树（balanced binary tree）：每个节点的左右子树高度相差不超过 1。AVL 树和红黑树是两种常见的自平衡二叉搜索树，它们在插入和删除后会自动调整，保持（近似）平衡。

判断方法：逐个节点计算左右子树的高度差。图中节点 1 的左右子树高度都是 2，差为 0；节点 2 的左子树高度为 1、右子树高度为 0，差为 1；节点 4 的左子树高度为 0、没有右子树（记为 −1），差为 1。所有节点的差都不超过 1，所以是平衡的。

满二叉树（full binary tree，按英文定义）：每个节点要么没有子节点，要么恰好有两个子节点，不存在只有一个子节点的节点。

二叉搜索树的复杂度

二叉搜索树（BST）要求：每个节点左子树中的所有值都小于它，右子树中的所有值都大于它。查找一个值时，从根节点开始比较，小于当前节点就往左走，大于就往右走。每走一步，就排除了另一边的整棵子树。

如果树是平衡的，每走一步大约排除一半的节点，查找只需要走 步。插入和删除也要先找到位置，所以同样是 。

图

图的概念

图由顶点（vertex）和连接顶点的边（edge）组成，用来表示事物之间的关系。

  • 有向图：边有方向，例如 B 站用户之间的关注关系（你关注了他，他不一定关注你）、两个城市之间的单向航线；
  • 无向图：边没有方向，例如微信好友关系、两个城市之间有没有铁路相连；
  • 有环图：存在一条从某个顶点出发、沿着边又回到它自己的路径；
  • 无环图：不存在这样的路径。有向无环图（DAG）常用来表示任务之间的依赖关系。

树是一种特殊的图：连通、无环的无向图。

图论还有很多重要的算法，例如最短路径（Dijkstra 算法）、最小生成树（Prim 算法和 Kruskal 算法）、拓扑排序，在地图导航、网络路由、社交网络分析中都有广泛应用。

今天的实证研究常用的双重差分和工具变量，背后是几个精彩的故事。1854 年伦敦霍乱，医生斯诺挨家挨户统计死亡、比较两家自来水公司的用户，在没有显微镜证据的情况下证明了霍乱经由饮水传播；1992 年新泽西提高最低工资，卡德和克鲁格打电话调查了 410 家快餐店，发现就业并没有像教科书预言的那样下降，引发了经济学界持续多年的争论；1969 年美国用抽签决定谁去越南打仗，安格里斯特用抽签号码估计服役对一生收入的影响。本篇讲这三个研究是怎样想到的、怎样做的、后来遇到了哪些质疑，以及它们怎样变成了今天教科书里的方法。
