Java 基础（二）：面向对象（上）——类、对象与封装

这是「Java 基础」的第二篇，完整的三篇是：

  1. 从 C 到 Java——环境、语法与数组
  2. 面向对象（上）——类、对象与封装（本篇）
  3. 面向对象（下）——继承、抽象类、接口与多态

本篇用一个“宠物管理软件”的例子贯穿始终。

面向过程与面向对象

C 语言是面向过程的：分析解决问题需要哪些步骤，用函数把每一步实现出来，然后按顺序调用。Java 是面向对象的：先想清楚问题里有哪些“东西”（对象），每个东西有什么特征、能做什么，再让这些对象相互配合完成任务。

以“狗饿了，狗吃东西”为例：

面向过程（POP） 面向对象（OOP）
思考方式 一件事“该怎么做”，像流水线 一件事“该让谁来做”，像模块化分工
代码 eat(dog, food); dog.eat(food);
重点 强调“吃”这个动作，“狗”只是一个参数 强调“狗”这个对象，“吃”是它的一个行为

一件事该让“谁”来做，那个“谁”就是对象。它具体怎么做是它自己的事，一群对象各司其职，合力把事情做好。程序规模变大时，面向对象更容易组织和维护：每个类只负责自己的数据和行为。

类与对象

类（class）是一类事物的模板，描述它们共同的特征和行为；对象（object，也叫实例）是按照模板创建出来的一个具体的个体。“狗”是一个类，你家那只叫 Tom 的哈士奇是一个对象。

C 语言的结构体只能存放数据，Java 的类既有数据，也有操作这些数据的函数：

public class Dogs {
    // 成员变量（属性）：描述狗的特征
    public String name;
    public String variety;
    public int age;
    public String food;

    // 成员方法（行为）：狗能做的事
    public void eat() {
        System.out.println(this.name + " eating food");
    }

    public void sleep() {
        System.out.println(this.name + " 狗在睡觉");
    }
}

用 new 创建对象，用 . 访问它的成员：

public class Main {
    public static void main(String[] args) {
        Dogs myDog = new Dogs();       // 按照 Dogs 这个模板，创建一个具体的狗
        myDog.name = "Tom";
        myDog.age = 2;
        myDog.variety = "哈士奇";
        myDog.sleep();
        myDog.eat();
        System.out.println("我的狗叫" + myDog.name);
    }
}

刚 new 出来的 myDog 只是“一只狗”，我们不知道它长什么样。给它的属性逐一赋值之后，它才变成一只具体的、独一无二的狗。

this

类中的方法里经常出现 this，它指的是调用这个方法的那个对象。

就像英语阅读理解里问“文中的 this 指代什么”，答案要看上下文。执行 myDog.sleep() 时，sleep 方法里的 this 就是 myDog，this.name 就是 "Tom"；如果另一只狗 yourDog 调用 yourDog.sleep()，同一行代码里的 this 就变成了 yourDog。

同一个类可以创建许多对象，它们共用方法的代码，但各自有一份成员变量。this 让方法知道当前操作的是哪一个对象的数据。

null 与空指针异常

Java 中，Dogs myDog 这样的变量存放的不是对象本身，而是对象的引用，可以理解成 C 语言中指向对象的指针。把它设为 null，表示它不再指向任何对象。

假设张大爷注销了账户：

public class Main {
    public static void main(String[] args) {
        Dogs zhangDog = new Dogs();
        zhangDog.name = "Tom";
        zhangDog.age = 2;
        zhangDog.variety = "哈士奇";
        zhangDog = null;                                   // 张大爷注销了账户
        System.out.println("zhangDog.name = " + zhangDog.name);
    }
}

zhangDog 已经不指向任何对象了，还要访问它的 name，程序就会抛出空指针异常（NullPointerException）。这和 C 语言里对空指针解引用是同一类错误，区别在于 Java 会抛出一个明确的异常，而不是产生不可预料的行为。

避免空指针异常的办法，是在使用之前检查引用是否为 null：

if (zhangDog != null) {
    System.out.println("zhangDog.name = " + zhangDog.name);
} else {
    System.out.println("这个账户已经注销");
}

封装

所有成员变量都是 public 的，任何代码都能随意修改：狗的年龄可以被改成 −30，银行账户的余额可以被改成 9999999。

封装的做法是：把成员变量设为 private（私有的，只有类自己的代码能访问），再提供 public 的 getter 和 setter 方法供外部读取和修改。

public class Dogs {
    private String name;
    private int age;

    public int getAge() {
        return age;
    }

    public void setAge(int age) {
        if (age < 0 || age > 30) {                         // 在 setter 里检查数据是否合理
            System.out.println("年龄不合法：" + age);
            return;
        }
        this.age = age;
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }
}

把成员变量改成 private 之后，main 里直接访问 zhangDog.name 会报错：

只能通过 getter 和 setter：

getter 和 setter 就像机器上的按钮：使用者不需要知道机器内部怎么运转，只能通过按钮操作；设计者可以在按钮背后加上检查，只有符合条件的操作才会执行。这就是封装的意义：隐藏内部细节，只暴露必要的接口，并保证数据始终有效。

IntelliJ IDEA 可以自动生成 getter 和 setter：在类中按 Alt + Insert，选择 Getter and Setter。

用 Lombok 省去样板代码

每个类都写一堆 getter 和 setter 很繁琐。Lombok 是一个第三方库，在类前面加上注解，编译时就会自动生成这些方法。

使用步骤（不使用 Maven 等构建工具，手动导入 jar 包）：

  1. 在 IntelliJ IDEA 的插件市场中安装 Lombok 插件（新版本的 IDEA 已经内置）：

  2. 从 Maven 仓库 下载 Lombok 的 jar 包：

  3. 在项目中新建一个 jar 文件夹，把下载的 jar 文件拖进去：

  4. 右键点击 jar 文件，选择 Add as Library，再选择 Project Library：

  5. 在设置的 Annotation Processors 中勾选 Enable annotation processing，然后重建项目：

之后，在类前面加上注解即可：

import lombok.Getter;
import lombok.Setter;

@Getter
@Setter
public class Dogs {
    private String name;
    private int age;
}

注意：用 @Setter 自动生成的 setter 只是简单地赋值。需要像上一节那样检查数据时，就要自己写这个 setter，Lombok 不会覆盖已经手写的方法。

toString

直接打印一个对象，得到的是类似 Dogs@1b6d3586 的字符串（类名和哈希码），看不出它的内容。在类中定义 toString() 方法，打印对象时就会使用它返回的字符串：

@Override
public String toString() {
    return "Dogs{name='" + name + "', variety='" + variety + "', age=" + age + "}";
}

同样可以用 Alt + Insert 选择 toString() 自动生成：

用 Lombok 的话，加上 @ToString 注解。更常用的是 @Data，它相当于同时加上 @Getter、@Setter、@ToString、@EqualsAndHashCode 和 @RequiredArgsConstructor。

构造方法

数组可以在定义时直接初始化：int[] arr = {1, 2, 3};。对象能不能在创建时就给属性赋值，而不是先 new 再一个个赋值？这就需要构造方法。

构造方法的规则：

  • 方法名和类名完全相同；
  • 没有返回值类型，连 void 都不写；
  • 用 new 创建对象时自动调用。
public class Dogs {
    private String name;
    private String variety;
    private int age;
    private String food;

    // 带参数的构造方法
    public Dogs(String name, String variety, int age, String food) {
        this.name = name;          // this.name 是成员变量，name 是参数
        this.variety = variety;
        this.age = age;
        this.food = food;
    }

    // 无参构造方法
    public Dogs() {
    }
}

参数名和成员变量名相同时，this.name 表示成员变量，单独的 name 表示参数。

现在创建对象时就可以直接初始化了：

Dogs zhangDog = new Dogs("Tom", "哈士奇", 2, "狗粮");

两点说明：

  • 如果一个类没有写任何构造方法，Java 会自动提供一个无参的构造方法。一旦写了带参数的构造方法，这个默认的无参构造方法就没有了，所以一般会再手动写一个无参的版本，以便 new Dogs() 依然可用（很多框架也要求类有无参构造方法）。
  • 构造方法也可以重载：上面的两个构造方法参数不同，new 的时候根据参数决定调用哪一个。一个构造方法里还可以用 this(...) 调用另一个构造方法，避免重复代码。

垃圾回收

C 语言中，用 malloc 申请的内存必须自己 free。Java 不需要：当一个对象不再被任何引用指向时（比如前面把 zhangDog 设成了 null），它就成了“垃圾”，JVM 的垃圾回收器会在适当的时候自动回收它占用的内存。

可以调用 System.gc() 建议 JVM 进行垃圾回收，但这只是一个“建议”，JVM 不一定立即执行，日常编程中几乎不需要调用它。

要注意的是，垃圾回收和空指针异常是两回事。上图的程序没有报错，是因为它打印的是 zhangDog 本身（输出 null），而不是 zhangDog.name。只要还通过一个值为 null 的引用去访问成员，无论是否调用 System.gc()，都会抛出空指针异常。

静态变量与静态方法

用 static 修饰的变量和方法属于类本身，而不属于某个对象：所有对象共享同一份静态变量，静态方法可以直接通过类名调用，不需要创建对象。

假设所有的狗都住在同一个小区：

public class Dogs {
    public static String plot = "NanG";               // 静态变量：所有狗共享

    public static void goPlot() {                      // 静态方法：通过类名调用
        System.out.println("所有狗都进了小区");
    }
}

// 在 main 中：
System.out.println("咱们的小区名是 " + Dogs.plot);
Dogs.goPlot();

main 方法也是 static 的，所以 JVM 不需要创建任何对象就可以调用它。反过来，静态方法里不能直接使用非静态的成员变量和 this，因为调用静态方法时，可能根本还没有任何对象。

用 private static 保护静态变量

public 的静态变量同样可以被随意修改，比如小区名被“黑”了：

做法和封装一样：把静态变量设为 private，只提供 getter：

public class Dogs {
    private static String plot = "NanG";

    public static String getPlot() {
        return plot;
    }
}

// 在 main 中：
System.out.println("Dogs.getPlot() = " + Dogs.getPlot());

如果这个值根本不应该改变，更好的做法是把它声明为常量 private static final，见下一篇的 final 一节。

单例模式

有些类在整个程序中只应该有一个实例，比如“地球”、程序的配置管理器、日志记录器。单例模式用 private 构造方法和 static 变量保证这一点：

public class Earth {
    // 在类内部创建唯一的实例，用 private static 保存
    private static final Earth INSTANCE = new Earth();

    // 构造方法是 private 的，外部无法 new Earth()
    private Earth() {
    }

    // 提供一个静态方法，返回唯一的实例
    public static Earth getInstance() {
        return INSTANCE;
    }

    public void showMessage() {
        System.out.println("Hello Earth!");
    }
}

public class Main {
    public static void main(String[] args) {
        // Earth earth = new Earth();      // 编译错误：Earth() 是 private 的
        Earth a = Earth.getInstance();
        Earth b = Earth.getInstance();
        a.showMessage();
        System.out.println(a == b);        // true：两次拿到的是同一个对象
    }
}

运行结果：

Hello Earth!
true

这里的写法叫“饿汉式”：类加载时就创建实例，简单而且线程安全。

参考：单例模式 - 菜鸟教程

内部类

类的里面还可以定义类，叫内部类：

  • 成员内部类：定义在类中，可以访问外部类的所有成员；
  • 静态内部类：用 static 修饰，只能直接访问外部类的静态成员；
  • 局部内部类：定义在方法里面，只能在这个方法中使用；
  • 匿名内部类：没有名字的局部内部类，下一篇会用到。

内部类适合只为外部类服务的辅助类，但用多了会让代码难以阅读和维护，初学时了解即可。

小结

  • 类是模板，对象是按模板创建的实例；对象的变量存放的是引用。
  • this 指调用当前方法的对象。
  • 通过值为 null 的引用访问成员，会抛出空指针异常。
  • 封装：成员变量 private，通过 getter/setter 访问，并在 setter 中检查数据。
  • 构造方法与类同名、没有返回值类型，在 new 时初始化对象。
  • Java 自动回收不再被引用的对象，不需要手动释放内存。
  • static 成员属于类，所有对象共享；单例模式用私有构造方法保证只有一个实例。
