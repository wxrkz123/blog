Python 从入门到精通（02）：变量、对象与内置类型

Python Python基础
Python
发布日期:   2026-10-07

如果只能从 Python 里挑一个最重要的概念，那一定是本篇的主题：对象与名字。几乎所有让初学者困惑的现象——修改一个列表另一个也跟着变、函数默认参数“记住”了上次的值、is 和 == 结果不一致——根源都在于没有建立正确的对象模型。本篇就来把这个模型彻底讲清楚，并顺带深入数字类型的底层表示。

本文是「Python 从入门到精通」系列第 02 篇，完整路线见 系列导读。

一、一切皆对象

在 Python 中，一切数据都是对象：数字、字符串、列表是对象，函数、类、模块也是对象，甚至“类型”本身也是对象。每个对象都有三个基本特征：

特征 含义 获取方式 能否改变
身份（identity） 对象在其生命周期内唯一的标识 id(obj) 永不改变
类型（type） 决定对象支持哪些操作、能取哪些值 type(obj) 永不改变（极少数特例除外）
值（value） 对象承载的数据 取决于类型 可变对象可以改，不可变对象不能改 
>>> x = 42
>>> type(x)
<class 'int'>
>>> isinstance(x, int)
True
>>> type(len), type(print)       # 函数也是对象
(<class 'builtin_function_or_method'>, <class 'builtin_function_or_method'>)
>>> type(int)                     # 类型也是对象，它的类型是 type
<class 'type'>
>>> type(type)                    # type 的类型是它自己
<class 'type'>

在 CPython 中，id(obj) 返回的就是对象在内存中的地址。这是一个实现细节，但它帮助我们理解：对象是内存中的一块数据，身份就是它的位置。

对象在 C 层面长什么样

CPython 中的每个对象，在 C 层面都以一个相同的头部开始（定义在 Include/object.h）：

typedef struct _object {
    Py_ssize_t ob_refcnt;     /* 引用计数：有多少个引用指向我 */
    PyTypeObject *ob_type;    /* 类型指针：我是什么类型 */
} PyObject;

所有对象都有这两个字段：引用计数用于内存管理（第 19 篇会详细讲），类型指针指向一个描述该类型行为的结构体。当你执行 x + y 时，解释器就是顺着 x 的类型指针，找到该类型定义的加法实现。这就是“对象的类型决定了它支持什么操作”的物理含义。

所以即使是一个小小的整数，也不是 C 语言里那 4 个字节，而是一个完整的对象：

>>> import sys
>>> sys.getsizeof(1)        # 一个整数对象占用的字节数（64 位 CPython 3.14）
28
>>> sys.getsizeof(1.0)
24
>>> sys.getsizeof(None)
16

这也是为什么处理大量数字时，NumPy 数组比 Python 列表省内存得多：NumPy 把数字以原始 C 类型紧密排列，而列表存的是一个个指向完整对象的指针。

二、变量是标签，不是盒子

很多语言的教材会把变量比作“盒子”：int a = 1; 就是造一个叫 a 的盒子，把 1 放进去。这个比喻在 Python 里是错误的。

Python 的变量更像是贴在对象上的标签（名字）。赋值语句 a = [1, 2, 3] 的真实含义是：

  1. 先求值右边，在内存中创建一个列表对象；
  2. 再把名字 a 绑定（bind）到这个对象上。
>>> a = [1, 2, 3]
>>> b = a              # 不是复制！只是给同一个对象再贴一个标签
>>> b.append(4)
>>> a
[1, 2, 3, 4]
>>> a is b             # 两个名字指向同一个对象
True
>>> id(a) == id(b)
True

用图来表示：

a ──┐
    ├──►  [1, 2, 3, 4]    （一个列表对象）
b ──┘

理解了这一点，很多现象就自然了：

  • 赋值永远不复制数据。b = a 只是让 b 也指向 a 所指的对象。需要副本时必须显式复制（a.copy()、list(a)、a[:]，或 copy 模块）。
  • 名字没有类型，对象才有类型。同一个名字可以先后绑定到不同类型的对象上，这就是“动态类型”的含义。
  • del a 删除的是名字，不是对象。对象只有在没有任何引用时才会被回收。
>>> a = [1, 2, 3]
>>> b = a
>>> del a              # 只是撕掉了标签 a
>>> b                  # 对象还在，因为 b 还贴着它
[1, 2, 3]
>>> a
Traceback (most recent call last):
  ...
NameError: name 'a' is not defined

名字存放在哪里：命名空间

名字和对象的绑定关系保存在命名空间（namespace）里，而模块级别的命名空间就是一个普通的字典：

>>> score = 95
>>> globals()["score"]
95
>>> globals()["level"] = "A"      # 直接往命名空间字典里写，等价于 level = "A"
>>> level
'A'

函数、类、模块各自有独立的命名空间。至于在函数里查找名字时按什么顺序搜索（著名的 LEGB 规则），我们留到 第 06 篇 讨论。

Python 是动态类型，但也是强类型

“动态类型”指名字没有固定类型，类型检查发生在运行时；“强类型”指不同类型之间不会偷偷进行隐式转换：

>>> x = 10
>>> x = "ten"        # 合法：名字 x 重新绑定到一个字符串对象
>>> "1" + 1          # 不合法：Python 不会自动把 1 变成 "1"（JavaScript 会）
Traceback (most recent call last):
  ...
TypeError: can only concatenate str (not "int") to str

三、is 与 ==：身份与相等

  • a is b 比较身份：两个名字是否指向同一个对象。它无法被重载，速度极快（本质是比较两个指针）。
  • a == b 比较值：两个对象是否“相等”。它会调用 a.__eq__(b)，具体含义由类型决定。
>>> x = [1, 2, 3]
>>> y = [1, 2, 3]
>>> x == y          # 值相等
True
>>> x is y          # 但是是两个不同的对象
False

规则：与单例比较时用 is，其他情况用 ==。 最常见的单例是 None，所以永远写 if x is None:，而不是 if x == None:。原因有二：is 更快，而且 == 可能被自定义类型重载成奇怪的行为（比如 NumPy 数组的 == 返回的是逐元素比较的数组）。

一个反直觉的例子：NaN

浮点数中的 NaN（Not a Number）有一个特殊性质：按照 IEEE 754 标准，它不等于任何值，包括它自己。

>>> nan = float("nan")
>>> nan == nan
False
>>> nan is nan
True
>>> [nan] == [nan]      # 但两个包含同一个 NaN 的列表却相等！
True
>>> nan in [nan]
True

最后两行为什么是 True？因为容器在比较元素时，为了性能和合理性，会先比较身份，身份相同就直接认为相等，不同才调用 ==。也就是说 x in container 的实际判定条件是 any(x is e or x == e for e in container)。这个细节在语言参考中有明确规定，平时很少遇到，但一旦遇到就会非常困惑。

四、可变对象与不可变对象

按照“值能否被原地修改”，内置类型可以分为两大类：

不可变（immutable） 可变（mutable）
int、float、complex、bool list
str、bytes dict
tuple、frozenset set
None bytearray
大多数自定义类的实例

“不可变”的意思是：对象一旦创建，它的值就不能再变。所有看似“修改”不可变对象的操作，实际上都是创建了一个新对象，再把名字重新绑定过去：

>>> s = "hello"
>>> old_id = id(s)
>>> s += " world"        # 创建了新字符串，s 被重新绑定
>>> id(s) == old_id
False

>>> lst = [1, 2]
>>> old_id = id(lst)
>>> lst += [3]           # 列表原地扩展，还是那个对象
>>> id(lst) == old_id
True

同样是 +=，作用在不可变对象和可变对象上，语义完全不同！这是因为增强赋值 a += b 的规则是：**如果 a 的类型实现了 __iadd__（原地加法），就调用它；否则退化为 a = a + b**。列表实现了 __iadd__，字符串和整数没有。

经典谜题：元组里的列表

理解了上面的规则，来看一个著名的 Python 谜题：

>>> t = (1, 2, [30, 40])
>>> t[2] += [50, 60]
Traceback (most recent call last):
  ...
TypeError: 'tuple' object does not support item assignment
>>> t                     # 报错了，但是……列表竟然被修改了！
(1, 2, [30, 40, 50, 60])

既报错又修改成功，这是怎么回事？t[2] += [50, 60] 实际上分为三步：

  1. 取出 t[2]，得到列表对象；
  2. 调用 列表.__iadd__([50, 60])，原地扩展了这个列表——此时修改已经发生；
  3. 把结果赋值回 t[2]，也就是执行 t[2] = 列表——元组不支持元素赋值，于是抛出 TypeError。

这个例子告诉我们三件事：不要把可变对象放进元组后再对它做增强赋值；增强赋值不是原子操作；以及“元组不可变”的准确含义是元组里保存的引用不能变，但被引用的对象本身如果可变，依然可以变。

可变性与哈希

只有“值不会变”的对象才适合做字典的键或集合的元素，因为哈希表依赖“对象的哈希值在其生命周期内保持不变”。所以：

>>> hash((1, 2, 3))      # 元组可哈希（前提是元素都可哈希）
529344067295497451
>>> hash([1, 2, 3])
Traceback (most recent call last):
  ...
TypeError: unhashable type: 'list'
>>> hash((1, [2, 3]))    # 元组里有列表，同样不可哈希
Traceback (most recent call last):
  ...
TypeError: unhashable type: 'list'

（整数元组的哈希值在不同运行之间是固定的；字符串的哈希值则会因为哈希随机化而每次运行都不同，这是为了防御哈希碰撞攻击。）

五、参数传递：既不是传值，也不是传引用

C++ 程序员常问：Python 函数参数是传值还是传引用？答案是都不是，官方的说法是“传对象引用”（call by object reference），也常被称为“共享传参”（call by sharing）：函数的形参会成为实参所指对象的又一个名字。

>>> def modify(items):
...     items.append(99)       # 通过新名字修改了共享的对象
...
>>> def rebind(items):
...     items = [0]            # 只是让局部名字 items 指向新对象，与外部无关
...
>>> data = [1, 2]
>>> modify(data)
>>> data
[1, 2, 99]
>>> rebind(data)
>>> data
[1, 2, 99]

用标签模型理解就非常清楚：调用 modify(data) 时，items 和 data 是贴在同一个列表上的两个标签。append 修改的是对象，所以外面看得到；items = [0] 只是把 items 这个标签撕下来贴到了别处，data 不受影响。

所以，一个函数能不能“修改调用者的数据”，取决于两点：传入的对象是否可变；函数是修改了对象，还是重新绑定了名字。

六、整数：任意精度的大数

Python 的 int 没有上限，只受内存限制：

>>> 2 ** 100
1267650600228229401496703205376
>>> len(str(2 ** 10000))      # 一个 3011 位的整数，算起来毫不费力
3011

内部表示

CPython 把大整数存成一个“数字”（digit）数组，每个 digit 存 30 个二进制位（这样两个 digit 相乘的结果能放进 64 位整数而不溢出）：

>>> import sys
>>> sys.int_info.bits_per_digit
30
>>> [sys.getsizeof(n) for n in (1, 2**30 - 1, 2**30, 2**60, 2**90)]
[28, 28, 32, 36, 40]

可以清楚地看到：每当数值超过 30 的整数倍个二进制位，对象就多出 4 字节，用来存放新的 digit。也就是说，整数可以看作一个以 2³⁰ 为基数的多位数，加减乘除都是用“竖式计算”的思路在这个数组上进行的（大数乘法还用了 Karatsuba 算法加速）。

这种设计的代价是：即使是很小的整数，运算也要经过通用的大数代码路径（尽管 CPython 对单 digit 的情况做了快速路径优化），所以 Python 整数运算比 C 的原生整数慢得多。

一个安全限制：整数转字符串的位数上限

把一个巨大的整数转成十进制字符串，算法复杂度是平方级的。攻击者如果能让服务器解析一个几十万位的数字，就可能造成拒绝服务。因此从 3.11 起，CPython 默认限制 int 与 str 之间转换的位数为 4300 位：

>>> sys.get_int_max_str_digits()
4300
>>> n = 10 ** 5000
>>> str(n)
Traceback (most recent call last):
  ...
ValueError: Exceeds the limit (4300 digits) for integer string conversion; use sys.set_int_max_str_digits() to increase the limit
>>> n.bit_length()      # 二进制相关的操作不受影响
16610

如果你确实需要处理超大整数（比如在做数论计算），可以用 sys.set_int_max_str_digits(0) 解除限制，或者用 hex() 等二进制基数的转换（它们是线性复杂度的，不受限制）。

整除与取模：向下取整

Python 的 // 是向下取整（floor division），这和 C、Java 的“向零截断”不同，差异只在负数时显现：

>>> 7 // 2, -7 // 2
(3, -4)
>>> 7 % 2, -7 % 2          # 余数的符号与除数相同
(1, 1)
>>> divmod(-7, 2)          # 同时得到商和余数
(-4, 1)
>>> int(-3.9)              # 而 int() 对浮点数是向零截断
-3

Python 选择向下取整是有深意的：它保证了 a == (a // b) * b + a % b 恒成立，且当 b > 0 时余数总在 [0, b) 区间内。这在计算“星期几”“循环数组下标”等场景下非常方便：(-1) % 7 直接得到 6，不需要额外处理负数。

七、浮点数：精确的近似

0.1 + 0.2 为什么不等于 0.3

>>> 0.1 + 0.2
0.30000000000000004
>>> 0.1 + 0.2 == 0.3
False

这不是 Python 的 bug，所有使用 IEEE 754 双精度浮点数的语言都是如此。浮点数用二进制表示小数，就像十进制无法精确表示 1/3 一样，二进制也无法精确表示 0.1（它是一个无限循环的二进制小数）。存进内存的只是一个最接近 0.1 的值。我们可以看看它的“真面目”：

>>> from decimal import Decimal
>>> Decimal(0.1)        # 把浮点数 0.1 的精确值完整展开
Decimal('0.1000000000000000055511151231257827021181583404541015625')
>>> (0.1).as_integer_ratio()     # 精确地表示为一个分数
(3602879701896397, 36028797018963968)
>>> (0.1).hex()                  # 十六进制的尾数与指数
'0x1.999999999999ap-4'

0x1.999999999999ap-4 清楚地展示了 IEEE 754 的结构：1 位符号、11 位指数、52 位尾数。尾数部分 999...9a 正是二进制循环小数被截断后舍入的结果。

那为什么 print(0.1) 显示的是 0.1 而不是那一长串？因为从 3.1 开始，repr(float) 使用“能唯一还原出这个浮点数的最短十进制字符串”。0.1 足以唯一确定那个二进制值，于是就显示 0.1；而 0.1 + 0.2 的结果是另一个二进制值，它最短的唯一表示是 0.30000000000000004。

正确比较浮点数

永远不要用 == 比较两个计算出来的浮点数，而应该比较它们的差是否足够小：

>>> import math
>>> math.isclose(0.1 + 0.2, 0.3)
True
>>> math.isclose(1e-10, 0)                  # 默认是相对误差，与 0 比较要指定绝对误差
False
>>> math.isclose(1e-10, 0, abs_tol=1e-9)
True

round 的“银行家舍入”

>>> round(2.5), round(3.5)      # 不是四舍五入，而是“四舍六入五成双”
(2, 4)
>>> round(2.675, 2)             # 看起来该是 2.68？
2.67

第一行是有意设计的：round 在恰好处于中间时，会舍入到最近的偶数。这种“银行家舍入”在大量数据求和时能避免系统性偏大。第二行则是浮点误差的又一个体现：2.675 在内存中实际是 2.67499999...，所以向下舍入了。

需要精确时：Decimal 与 Fraction

涉及金额等需要精确十进制运算的场景，使用 decimal 模块；需要精确有理数运算时，使用 fractions 模块：

>>> from decimal import Decimal, ROUND_HALF_UP
>>> Decimal("0.1") + Decimal("0.2")          # 注意用字符串构造！
Decimal('0.3')
>>> Decimal("2.675").quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)
Decimal('2.68')
>>> from fractions import Fraction
>>> Fraction(1, 3) + Fraction(1, 6)
Fraction(1, 2)

一个常见错误是写 Decimal(0.1)：浮点数 0.1 在传给 Decimal 之前就已经不精确了，Decimal 只是忠实地还原了这个不精确的值。一定要用字符串构造 Decimal。

特殊值

>>> float("inf") > 10 ** 308
True
>>> float("inf") - float("inf")
nan
>>> import sys
>>> sys.float_info.max, sys.float_info.epsilon
(1.7976931348623157e+308, 2.220446049250313e-16)
>>> 1e308 * 10           # 浮点数溢出得到 inf，而不是报错
inf
>>> 10 ** 400 * 1.0      # 但大整数转浮点数溢出会报错
Traceback (most recent call last):
  ...
OverflowError: int too large to convert to float

sys.float_info.epsilon 是“1.0 和比 1.0 大的最小浮点数之间的差”，它刻画了双精度浮点数大约 15～16 位有效十进制数字的精度。

八、布尔值与 None

bool 是 int 的子类

>>> issubclass(bool, int)
True
>>> True + True, True * 10
(2, 10)
>>> sum([True, False, True, True])   # 常用技巧：统计满足条件的元素个数
3

这是历史原因造成的（Python 早期没有 bool 类型，用 1 和 0 表示真假），但也带来了实用性：sum(x > 0 for x in data) 可以直接统计正数个数。

真值测试

任何对象都可以放在 if 或 while 中做条件判断。判断规则是：

  1. 如果对象定义了 __bool__，调用它；
  2. 否则如果定义了 __len__，长度为 0 则为假；
  3. 否则为真。

因此以下值被视为假：None、False、数值零（0、0.0、0j、Decimal(0)）、空容器（""、[]、()、{}、set()、range(0)）。这让我们可以写出简洁的 if items: 来代替 if len(items) > 0:。

但要小心：if x: 和 if x is not None: 不等价。如果 x 可能是 0 或空字符串这类合法值，就必须显式写 is not None。

None：唯一的“无”

None 是 NoneType 类型的唯一实例，即单例（singleton）。函数没有 return 语句时返回的就是它。因为是单例，所有的 None 都是同一个对象，这正是可以用 is None 判断的原因。

与之类似的单例还有 Ellipsis（即 ...，常用于 NumPy 切片和类型注解中的占位）和 NotImplemented（二元运算方法用它表示“我不知道怎么处理这个类型”，我们会在 第 10 篇 讲到）。

九、对象缓存：is 的陷阱

小整数缓存

>>> a = 256
>>> b = 256
>>> a is b
True
>>> a = 257
>>> b = 257
>>> a is b        # 在交互式解释器中逐行输入时
False

CPython 在启动时预先创建了 -5 到 256 之间的所有整数对象，之后任何地方用到这些值，都直接复用这些预先创建的对象，而不是新建。这是因为小整数使用得极其频繁（循环计数、下标……），缓存能省下大量的内存分配。超出这个范围的整数，每次计算都会创建新对象。

但是，如果你把 a = 257; b = 257; print(a is b) 写进一个脚本文件运行，结果却可能是 True！因为同一个代码块中的相同常量会被编译器合并成同一个对象。这再次说明：**is 的结果对于数字和字符串来说依赖于实现细节，绝不能用 is 比较数值或字符串的值**。从 3.8 开始，用 is 和字面量比较会直接触发 SyntaxWarning 来提醒你这一点。

字符串驻留

类似地，CPython 会对一部分字符串做驻留（interning）：看起来像标识符的字符串字面量（只含字母、数字、下划线）、变量名、属性名等会被放进一个全局表中复用。这让字典查找属性名时可以先用指针比较，大大加快速度。你也可以用 sys.intern() 手动驻留字符串，在需要大量比较同样字符串的场景下节省内存和时间。同样，这是优化手段，不是语义保证。

不朽对象

从 3.12 开始（PEP 683），None、True、False、小整数等对象被标记为不朽对象（immortal objects）：它们的引用计数被设为一个特殊的大值，并且永远不会被修改或回收。

>>> sys._is_immortal(None), sys._is_immortal(42)   # 3.14 新增的检查函数
(True, True)
>>> sys._is_immortal([])
False

这样做的好处是，这些被极其频繁使用的对象不再需要更新引用计数，既减少了内存写入，又让它们可以在多个解释器、多个线程之间安全共享而无需加锁——这是实现“自由线程”（无 GIL）Python 的重要基础之一，我们会在 第 17 篇 再次提到。

十、类型转换速查

>>> int("42"), int("  -7  "), int("1_000_000")     # 允许首尾空白和数字分隔下划线
(42, -7, 1000000)
>>> int("ff", 16), int("0b1010", 0)               # 指定进制；0 表示根据前缀自动识别
(255, 10)
>>> float("3.14"), float("1e-3"), float("inf")
(3.14, 0.001, inf)
>>> str(3.14), repr("a\nb")                        # str 面向用户，repr 面向开发者
('3.14', "'a\\nb'")
>>> bool("False")                                   # 非空字符串都是真！
True
>>> int("3.14")
Traceback (most recent call last):
  ...
ValueError: invalid literal for int() with base 10: '3.14'

最后两个是常见坑：bool("False") 为真，因为它是一个非空字符串；int("3.14") 会失败，需要先 float 再 int。

小结

  • 对象有身份、类型、值三要素；CPython 中每个对象都以“引用计数 + 类型指针”开头。
  • 变量是贴在对象上的标签。赋值只绑定名字，从不复制数据；del 删除名字而非对象。
  • is 比较身份，== 比较值；只有和 None 这类单例比较时才用 is。
  • += 对可变对象原地修改，对不可变对象重新绑定；参数传递是“共享传参”。
  • int 是任意精度的，内部以 30 位为一个 digit；// 向下取整。
  • float 是 IEEE 754 双精度，用 math.isclose 比较，用字符串构造 Decimal 做精确计算。
  • 小整数缓存、字符串驻留、不朽对象都是实现层面的优化，不能作为语义依赖。
