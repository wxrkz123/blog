Python 环境怎么装：python.org、conda、venv 与 uv 怎么选

学 Python 的第一道坎往往不是语法，而是环境：pip install pandas 明明成功了，import pandas 却报错；装了一个新库，原来能运行的代码不能运行了；教程里的命令在自己的电脑上提示“不是内部或外部命令”。这些问题几乎都来自同一个原因：电脑上有不止一个 Python，而你没有意识到自己在用哪一个。

这篇文章先讲清楚几个概念，再给出三种安装方案和选择的建议。

一、四个概念

解释器：真正运行 Python 代码的程序（python.exe 或 python3）。一台电脑上可以有好几个：系统自带的、自己从官网装的、Anaconda 带的、某个软件附带的。

包（package）：别人写好的代码，比如 pandas、statsmodels。包安装在某一个解释器的目录下（site-packages），只有这个解释器能用。

包管理器：下载和安装包的工具。最常见的是 Python 自带的 pip，此外还有 conda 和 uv。

虚拟环境：一个独立的小环境，有自己的解释器入口和自己的 site-packages。每个项目使用自己的虚拟环境，不同项目可以使用不同版本的包，互不干扰。

为什么需要虚拟环境？设想两个项目：一个是三年前的论文，依赖 pandas 1.x；一个是新项目，用 pandas 3。如果所有的包都装在同一个地方，升级 pandas 就会让旧项目无法运行。虚拟环境还让项目可以复现：把环境中所有包的版本记录下来，别人（或者一年后的自己）就能重建一模一样的环境（实证研究工作流第 01 篇）。

二、三种方案

方案一：官方安装包 + venv + pip

最“原汁原味”的方式，所有工具都来自 Python 官方。

安装 Python：从 python.org 下载安装包。Windows 上安装时一定勾选“Add python.exe to PATH”（把 Python 加入系统路径），否则在命令行中找不到 python 命令。macOS 可以用官网安装包，也可以用 Homebrew（brew install python）。Linux 通常自带 Python 3，用系统的包管理器安装 python3-venv 即可。

为每个项目建立虚拟环境。在项目文件夹中打开命令行（命令行入门）：

python -m venv .venv                 # 在当前文件夹中创建名为 .venv 的虚拟环境（macOS/Linux 上可能要写 python3）

# 激活虚拟环境
.venv\Scripts\activate               # Windows（命令提示符或 PowerShell）
source .venv/bin/activate            # macOS / Linux

python -m pip install pandas statsmodels matplotlib    # 安装的包只进入这个环境
python -m pip freeze > requirements.txt                # 记录所有包的版本
deactivate                                             # 退出虚拟环境

激活之后，命令行的提示符前面会出现 (.venv)，此时的 python、pip 都是这个环境里的。别人拿到项目后，建立自己的虚拟环境，运行 python -m pip install -r requirements.txt，就得到了同样版本的包。

优点：标准、通用，所有教程都适用。缺点：需要自己安装和管理不同版本的 Python；pip 比较慢。

方案二：conda（Anaconda 或 Miniforge）

conda 既是包管理器，也能管理 Python 本身的版本，还能安装非 Python 的依赖（比如某些科学计算库需要的 C/Fortran 库）。

  • Anaconda：一个安装包里带好了 Python、几百个常用的科学计算包、Jupyter 和图形界面的管理工具，装完就能用，对完全的新手最省事。缺点是体积大（几个 GB），而且 Anaconda 默认软件源的使用条款对较大机构的商业使用有付费要求，在公司或机构使用前要确认；
  • Miniforge：只带 conda 本身和最基本的组件，默认使用社区维护的 conda-forge 软件源，体积小，没有上面的条款问题。需要什么包自己装。
conda create -n econ python=3.12 pandas statsmodels matplotlib jupyterlab   # 建立名为 econ 的环境
conda activate econ
conda install -c conda-forge linearmodels                                   # 从 conda-forge 安装
conda env export --from-history > environment.yml                           # 记录环境
conda env create -f environment.yml                                         # 别人重建同样的环境

和 venv 不同，conda 的环境默认集中存放在 conda 的安装目录下，用名字（-n econ）区分，不在项目文件夹里。

注意不要混用：在 conda 环境中，尽量用 conda install 安装；conda 上没有的包再用 pip install，而且最好在 conda 的包都装完之后再用 pip。两者交替安装，容易出现依赖冲突。

方案三：uv

uv 是近两年迅速流行起来的新工具，它把“安装 Python”“建立虚拟环境”“安装包”“记录依赖”合并成一个工具，而且安装包的速度比 pip 快得多（通常快 10 倍以上）。安装 uv 只需要按官网的说明运行一行命令。

最简单的用法和 venv + pip 几乎一样，只是在命令前面加上 uv：

uv venv                               # 在当前文件夹创建 .venv
uv pip install pandas statsmodels     # 装进 .venv（不需要先激活）
uv python install 3.12                # 顺便还能安装指定版本的 Python

更推荐的是“项目”的用法：uv 自动维护一个记录依赖的 pyproject.toml 和一个锁定所有包精确版本的 uv.lock：

uv init                               # 把当前文件夹初始化为一个项目（生成 pyproject.toml 等文件）
uv add pandas statsmodels matplotlib  # 添加依赖：写入 pyproject.toml，更新 uv.lock，装进 .venv
uv run python analysis.py             # 在项目的环境中运行脚本

别人拿到项目后只需要运行 uv sync，就能得到和你完全相同的环境（包括 Python 的版本）。这是目前最省事、可复现性最好的方式。

怎么选

你的情况 建议
完全的新手，只想尽快开始写代码 Anaconda（个人学习使用），或者 Miniforge
需要很多非 Python 的科学计算依赖（GDAL 等地理信息库、某些 GPU 库） conda（Miniforge）
已经熟悉命令行，想要快速、可复现的项目环境 uv
需要和别人的教程、服务器环境完全一致 官方 Python + venv + pip

无论选哪一种，原则都一样：每个项目一个环境，记录所有包的版本。本站各系列的导读都写明了需要安装的包和测试时使用的 Python 版本。

三、确认自己在用哪个 Python

遇到“装了却找不到”的问题时，第一件事是确认当前用的是哪一个解释器。在 Python 中运行：

import sys
print(sys.executable)                    # 当前解释器的路径
print(sys.version)
print("在虚拟环境中：", sys.prefix != sys.base_prefix)

如果路径在项目的 .venv 文件夹（或者 conda 的 envs/环境名）里，说明用的是虚拟环境；如果是系统目录下的 Python，说明虚拟环境没有激活，或者编辑器选错了解释器。

在命令行中，where python（Windows）或 which python（macOS、Linux）列出 python 命令对应的所有程序，第一个就是实际被调用的那个。

安装包时用 python -m pip install ...，而不是直接写 pip install ...。python -m pip 保证包装进当前这个 python 对应的环境；单独的 pip 命令可能属于另一个 Python。

四、编辑器和 Jupyter

VS Code

VS Code 是目前最常用的免费代码编辑器。安装 Microsoft 发布的 Python 和 Jupyter 两个扩展之后：

  1. 用“文件 → 打开文件夹”打开项目文件夹；
  2. 按 Ctrl+Shift+P（macOS 是 Cmd+Shift+P），输入“Python: Select Interpreter”，选择项目的 .venv 或 conda 环境；
  3. 窗口右下角（或笔记本的右上角）会显示当前使用的环境，运行代码前看一眼。

JupyterLab

在环境中安装并启动 JupyterLab：

python -m pip install jupyterlab      # 或 uv pip install jupyterlab / conda install jupyterlab
jupyter lab                           # 在浏览器中打开 JupyterLab

笔记本中的代码由一个内核（kernel）运行，内核就是某一个环境中的 Python。如果 JupyterLab 装在一个环境里，又想用另一个环境运行笔记本，要把那个环境注册为一个内核：

# 在要注册的环境中运行
python -m pip install ipykernel
python -m ipykernel install --user --name econ --display-name "Python (econ)"

之后在 JupyterLab 右上角就可以选择“Python (econ)”。

打开本站的笔记本

本站每篇含有代码的文章，顶部都有“下载 Jupyter 笔记本”的链接，系列文章还可以下载整个系列的压缩包。笔记本里的代码和文章完全一致。使用方法：

  1. 下载 .ipynb 文件，放进一个项目文件夹（需要数据文件的，按系列导读的说明一起下载）；
  2. 在这个文件夹中建立虚拟环境，安装系列导读“环境准备”中列出的包；
  3. 用 VS Code 或 JupyterLab 打开，选择这个环境作为内核，从上到下依次运行。

五、常见问题

ModuleNotFoundError: No module named 'pandas'，但我明明装过了

包装进了另一个 Python。按第三节的方法确认当前的解释器，然后用 python -m pip install pandas 在这个解释器中安装；在编辑器中检查选择的解释器或内核。

在 Jupyter 笔记本里 !pip install 之后还是找不到

!pip 在系统的命令行中执行 pip，它可能属于另一个 Python。在笔记本中安装包要用 %pip install pandas：这个“魔法命令”保证包装进当前内核所在的环境。

“python 不是内部或外部命令”

Windows 上安装 Python 时没有勾选“Add to PATH”。重新运行安装程序选择“Modify”加上，或者使用 py 启动器（官方安装包自带）：py -m venv .venv。

下载很慢或超时

在中国大陆访问 PyPI 可能较慢，可以使用国内的镜像，比如清华大学的镜像：

python -m pip install pandas -i https://pypi.tuna.tsinghua.edu.cn/simple                  # 单次使用
python -m pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple        # 设为默认

conda 和 uv 也有对应的镜像设置方法，见各镜像站的说明。

权限错误（Permission denied）

不要用管理员权限（sudo pip install）往系统的 Python 里装包，这可能破坏操作系统自带的工具。使用虚拟环境，所有的包都装在自己的项目文件夹里，不需要管理员权限。

装了新包之后，原来的代码报错了

新包升级了某个共用的依赖。这正是每个项目一个环境、并记录版本的原因：用 requirements.txt、environment.yml 或 uv.lock 恢复原来的版本。

小结

  • 解释器运行代码，包装在某个解释器的环境里，包管理器负责安装，虚拟环境让每个项目有独立的包。
  • 三种方案：官方 Python + venv + pip（标准、通用），conda（省事、能装非 Python 依赖），uv（快、可复现性最好）。
  • 每个项目一个环境，用 requirements.txt、environment.yml 或 uv.lock 记录版本。
  • “装了却找不到”时，先用 sys.executable 确认当前的解释器；安装用 python -m pip，笔记本中用 %pip。
  • 在 VS Code 中选择解释器、在 Jupyter 中选择内核，就是选择用哪个环境运行代码。
