Java 基础（三）：面向对象（下）——继承、抽象类、接口与多态

这是「Java 基础」的第三篇，完整的三篇是：

  1. 从 C 到 Java——环境、语法与数组
  2. 面向对象（上）——类、对象与封装
  3. 面向对象（下）——继承、抽象类、接口与多态（本篇）

面向对象有三大特性：封装、继承、多态。上一篇讲了封装，这一篇讲另外两个。例子继续沿用宠物管理软件。

继承

为什么需要继承

宠物不只有狗，还有猫、仓鼠、兔子……如果每种动物都写一个类，会发现名字、品种、年龄、食物这些属性，吃饭、睡觉这些行为，在每个类里都要重复写一遍。

继承就是把这些共同的部分提取到一个父类中，其他类通过 extends 关键字继承它，自动拥有父类的属性和方法：

public class Animal {               // 父类：所有动物的共同部分
    private String name;
    private String variety;
    private int age;
    private String food;

    // 省略 getter、setter 和构造方法

    public void eat() {
        System.out.println(name + " eating " + food);
    }
}

public class Dogs extends Animal {  // 子类：Dogs 继承了 Animal 的所有内容
}

public class Cat extends Animal {
}

Dogs 和 Cat 的类体是空的，但它们已经有了 Animal 的全部属性和方法，可以像以前一样使用。把共同的代码放在父类中，子类只写自己特有的部分，代码的复用性大大提高；要修改共同的行为，也只需要改父类一个地方。

继承表达的是“是一个”（is-a）的关系：狗是一种动物，猫是一种动物。

注意：父类中 private 的成员，子类虽然“拥有”，但不能直接访问，要通过父类提供的 getter、setter（或者把它们声明为 protected，见本文最后的权限修饰符）。

多层继承

继承可以有多层，就像爷爷 → 爸爸 → 儿子：

public class Dogs extends Animal {
}

public class Labrador extends Dogs {    // 拉布拉多是一种狗，狗是一种动物
}

Labrador 同时拥有 Dogs 和 Animal 的成员。

但 Java 是单继承的：一个类只能直接继承一个父类，不能写成 class A extends B, C。这避免了多个父类中有同名方法时“该用哪一个”的混乱。需要“继承”多个类型的行为时，用本文后面的接口。

方法重写

子类可以改写父类的方法

狗和猫都会叫，但叫声不同。子类可以重写（override）父类的方法，提供自己的实现：

public class Animal {
    public void barking() {
        System.out.println("动物叫");
    }
}

public class Dogs extends Animal {
    @Override
    public void barking() {
        System.out.println("汪汪");
    }
}

public class Cat extends Animal {
    @Override
    public void barking() {
        System.out.println("喵喵");
    }
}

@Override 注解告诉编译器“这个方法是重写父类的”。如果方法名或参数写错了，父类中没有对应的方法，编译器就会报错。它不是必需的，但强烈建议加上。

重写的规则：方法名和参数列表必须和父类完全相同；返回值类型相同（或者是其子类型）；访问权限不能比父类更严格（父类是 public，子类就不能改成 private）。

重写与重载的区别

重写（Override） 重载（Overload）
发生在 子类和父类之间 同一个类中
方法名 相同 相同
参数列表 必须相同 必须不同
作用 子类改写父类的实现 同一个功能接受不同类型的参数

参考：Java 重写与重载 - 菜鸟教程

super：调用父类的版本

在子类中，super.方法名() 调用父类的版本。如果子类不想完全推翻父类的做法，而是在它的基础上补充，就可以这样写：

public class Cat extends Animal {
    @Override
    public void barking() {
        super.barking();               // 先执行父类的 barking：输出“动物叫”
        System.out.println("喵喵");     // 再加上自己的部分
    }
}

IntelliJ IDEA 自动生成重写方法时，会在方法体里默认写上一行 super.xxx()。如果要完全替换父类的行为，就把这一行删掉；保留它，就会先执行父类的版本。

子类的构造方法

构造方法不会被继承，也谈不上重写。子类要定义自己的构造方法，并在第一行用 super(...) 调用父类的构造方法，初始化从父类继承来的那部分属性：

public class Animal {
    private String name;
    private String variety;
    private int age;
    private String food;

    public Animal(String name, String variety, int age, String food) {
        this.name = name;
        this.variety = variety;
        this.age = age;
        this.food = food;
    }

    public Animal() {
    }
}

public class Cat extends Animal {
    public Cat(String name, String variety, int age, String food) {
        super(name, variety, age, food);       // 必须是第一条语句
    }

    public Cat() {
        // 没有显式写 super(...) 时，编译器会自动插入 super()，调用父类的无参构造方法
    }
}

在 IntelliJ IDEA 中按 Alt + Insert，选择 Constructor，再选择要调用的父类构造方法，就能自动生成：

如果父类没有无参构造方法，子类的构造方法又没有显式调用 super(...)，编译就会报错。这也是上一篇建议“写了带参数的构造方法，再补一个无参的”的原因之一。

final

final 表示“最终的、不可改变的”，可以修饰类、方法和变量：

修饰 含义 例子
类 不能被继承 String 类就是 final 的
方法 不能被子类重写
变量 只能赋值一次，即常量 final double PI = 3.14159;

比如“是否是导盲犬”的判断由 Dogs 类统一规定，不允许子类修改：

public class Dogs extends Animal {
    public final boolean isGuideDog() {
        return false;
    }
}

public class Labrador extends Dogs {
    @Override
    public boolean isGuideDog() {      // 编译错误
        return true;
    }
}

IntelliJ IDEA 会给出这样的错误提示（命令行 javac 的措辞略有不同，意思一样）：

'isGuideDog()' cannot override 'isGuideDog()' in 'com.microsoft.demo.Dogs'; overridden method is final

static final 的变量是类级别的常量。按照命名规范，常量名全部大写，单词之间用下划线分隔：

private static final String COMMUNITY_NAME = "NanG";

public static String getCommunityName() {
    return COMMUNITY_NAME;
}

IntelliJ IDEA 的快捷键：Ctrl + Shift + U 切换选中文字的大小写，Shift + F6 重命名变量（所有用到它的地方会一起修改）。

抽象类

一个新问题

Animal 类是用来被继承的。现实中没有人养一只抽象的“动物”，养的总是具体的猫、狗、仓鼠。那么 new Animal() 有意义吗？

另一个问题：如果新增了一个仓鼠类，却忘了重写 barking()，仓鼠叫的时候输出的就是父类的“动物叫”，程序不会报任何错误。

抽象类同时解决了这两个问题。

抽象类与抽象方法

用 abstract 修饰的类是抽象类，它不能被 new，只能被继承。抽象类中可以有抽象方法：只有声明、没有方法体的方法。

public abstract class Animal {
    private String name;

    // 抽象方法：所有动物都会叫，但怎么叫，由具体的动物决定
    public abstract void barking();

    // 抽象类中也可以有普通的方法
    public void eat() {
        System.out.println(name + " is eating");
    }
}

规则：

  • 继承抽象类的子类，必须重写所有的抽象方法，否则它自己也必须声明为抽象类。忘记重写时编译器会报错，这就解决了“仓鼠忘了定义叫声”的问题；
  • 抽象方法只能出现在抽象类（或接口）中；
  • 抽象方法没有方法体，所以子类重写它时，不能再调用 super.barking()。
public class Cat extends Animal {
    @Override
    public void barking() {
        System.out.println("喵喵");
    }
}

抽象类抽取了一类具体事物的共性，“抽象”的目的是为了概括具体的事物。

接口

全是抽象方法的“类”

如果一个抽象类里的方法全都是抽象的，就可以用接口（interface）来代替它。接口描述的是“能做什么”，而不关心“是什么”。

在 IntelliJ IDEA 中新建时选择 Interface：

public interface Human {
    void eat();         // 接口中的方法默认就是 public abstract 的，可以省略这两个关键字
    void run();
}

类用 implements 关键字实现接口，必须实现接口中的所有抽象方法：

public class Chinese implements Human {
    @Override
    public void eat() {
        System.out.println("吃中餐");
    }

    @Override
    public void run() {
        System.out.println("小跑");
    }
}

public class Westerner implements Human {
    @Override
    public void eat() {
        System.out.println("吃西餐");
    }

    @Override
    public void run() {
        System.out.println("大步跑");
    }
}

public class Application {
    public static void main(String[] args) {
        Chinese chinese = new Chinese();
        chinese.eat();
        chinese.run();

        Westerner westerner = new Westerner();
        westerner.eat();
        westerner.run();
    }
}

运行结果：

吃中餐
小跑
吃西餐
大步跑

一个类只能继承一个父类，但可以实现多个接口：class Dog extends Animal implements Runnable, Swimmable。这弥补了单继承的限制。

从 Java 8 开始，接口中也可以有带方法体的 default 方法和 static 方法，所以“接口里全是抽象方法”的说法已经不完全准确，但接口的主要用途仍然是定义一组抽象的行为。

抽象类与接口的区别

抽象类 接口
关键字 abstract class，子类用 extends interface，实现类用 implements
一个类可以 只继承一个 实现多个
成员变量 可以有普通的成员变量 只能有常量（默认 public static final）
构造方法 有 没有
方法 抽象方法和普通方法都可以有 抽象方法，以及 Java 8 起的 default、static 方法
表达的关系 “是一个”（is-a）：猫是一种动物 “能做”（can-do）：人能吃、能跑

经验上：抽取一类事物的共同属性和行为时用抽象类；定义一种能力、一组行为规范时用接口，接口名常常是形容词或动词，比如 Comparable（可比较的）、Runnable（可运行的）。

多态

同一个行为，不同的表现

多态指同一个行为有多种不同的表现形式：同样是“叫”，狗是“汪汪”，猫是“喵喵”。在代码中，就是用父类类型的变量，引用子类的对象，调用方法时执行的是子类的版本。

多态需要三个条件：

  1. 有继承（或实现接口）；
  2. 子类重写了父类的方法；
  3. 父类的引用指向子类的对象：Animal a = new Cat();
public class Application {
    public static void main(String[] args) {
        Animal[] pets = {new Dogs(), new Cat()};
        for (Animal pet : pets) {
            pet.barking();          // 同一行代码，对不同的对象产生不同的结果
        }
    }
}

运行结果：

汪汪
喵喵

多态的好处是：处理动物的代码（比如这个循环）只需要知道 Animal 类型。以后再增加兔子、仓鼠，这段代码一行都不用改。

向上转型与向下转型

向上转型：把子类对象当作父类类型使用，自动完成，总是安全的。就像花木兰替父从军，以“父亲”的身份出现，隐藏了自己的身份：

Animal a = new Cat();      // 向上转型
a.barking();               // 执行的是 Cat 的 barking

向上转型后，通过 a 只能调用 Animal 中定义的方法，Cat 特有的方法调用不了。

向下转型：把父类类型的引用转回子类类型，要用强制类型转换。它的前提是，这个引用实际指向的本来就是该子类的对象，就像花木兰卸甲之后做回自己：

Cat c = (Cat) a;           // 可以：a 实际指向的就是一只猫
Dogs d = (Dogs) a;         // 编译能通过，但运行时抛出 ClassCastException：猫不能变成狗

为了安全，向下转型之前用 instanceof 检查：

if (a instanceof Cat) {
    Cat c = (Cat) a;
}

if (a instanceof Cat c) {  // Java 16 起的简写：检查并直接转换成变量 c
    c.barking();
}

参考：Java 中的多态 - 菜鸟教程

匿名内部类

抽象类和接口都不能直接 new。但如果某个实现只用一次，专门写一个类太麻烦，可以用匿名内部类：在 new 的同时，直接写出类体。

public class Application {
    public static void main(String[] args) {
        Human xiaoming = new Human() {          // 定义一个实现了 Human 的匿名类，并创建它的对象
            @Override
            public void eat() {
                System.out.println("吃中国菜");
            }

            @Override
            public void run() {
                System.out.println("跑步");
            }
        };
        xiaoming.eat();
    }
}

运行结果：

吃中国菜

看起来像是“new 了一个接口”，实际上编译器创建了一个没有名字的类，这个类实现了 Human 接口，然后 new 的是这个匿名类的对象。所以必须实现接口中的所有抽象方法。对抽象类也可以这样做：new Animal() { ... }。

对于只有一个抽象方法的接口，Java 8 起还可以用更简洁的 lambda 表达式 代替匿名内部类，例如 Runnable r = () -> System.out.println("run");。

访问权限修饰符

Java 有四种访问权限，从宽到严：

修饰符 同一个类 同一个包 不同包的子类 其他任何地方
public ✓ ✓ ✓ ✓
protected ✓ ✓ ✓
不写（默认） ✓ ✓
private ✓

常见的用法：成员变量用 private，对外提供的方法用 public，只希望子类使用的成员用 protected。

参考：Java 修饰符 - 菜鸟教程

Object 类

java.lang.Object 是所有类的祖先。定义一个类时，如果没有写 extends，它就自动继承 Object。所以任何对象都有 Object 定义的方法，最常用的三个是：

方法 作用 默认行为
toString() 返回对象的字符串表示 类名 + @ + 哈希码，通常需要重写（上一篇的 toString 一节）
equals(Object o) 判断两个对象的内容是否相等 和 == 一样，比较是否是同一个对象
hashCode() 返回哈希码，用于 HashMap、HashSet 由对象的内存地址等信息计算

重写 equals 时必须同时重写 hashCode，保证内容相等的两个对象哈希码也相等，否则放进 HashMap、HashSet 时会出问题。Lombok 的 @EqualsAndHashCode（或 @Data）可以自动生成这两个方法。

参考：Java Object 类 - 菜鸟教程

小结

概念 要点
继承 extends，子类复用父类的代码；Java 只支持单继承
重写 子类改写父类的方法，加 @Override；用 super.方法() 调用父类的版本
构造方法 不会被继承，子类在第一行用 super(...) 调用父类的构造方法
final 类不能被继承，方法不能被重写，变量不能被修改
抽象类 不能 new；子类必须重写所有抽象方法
接口 定义一组行为，一个类可以实现多个接口
多态 父类引用指向子类对象，调用的是子类的方法；向下转型前用 instanceof 检查

三篇「Java 基础」到这里就结束了。接下来可以学习 Java 的异常处理、集合框架（ArrayList、HashMap）、泛型和输入输出。如果想用 C 语言加深对数据结构的理解，可以看《用 C 语言实现常用数据结构》。
