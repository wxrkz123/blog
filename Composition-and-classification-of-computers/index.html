看懂电脑配置：CPU、内存、硬盘、显卡各管什么

这篇文章最初写于 2023 年，介绍的是当时的具体硬件型号。型号每年都在更新，2026 年重写时删去了所有具体型号和购买推荐，只保留不会过时的原理，并加入了做数据分析时最常遇到的硬件问题。

买电脑、看配置单、或者程序跑得很慢想找原因时，都会碰到一堆参数：8 核 16 线程、16 GB 内存、512 GB 固态硬盘、独立显卡。这篇文章解释这些部件各自管什么，以及它们怎样影响你每天用电脑做的事情。

一、一台电脑的组成

一台电脑的核心部件可以归为四类，它们都插在主板上，通过主板上的线路交换数据：

部件 负责什么 关键参数
CPU（中央处理器） 执行程序的每一条指令：计算、比较、决定下一步做什么 核心数、频率、缓存
内存（RAM） 存放正在运行的程序和正在处理的数据，断电后清空 容量（GB）、速度
硬盘（存储） 长期保存文件、程序和系统，断电后不丢失 容量、类型（固态/机械）、读写速度
显卡（GPU） 把画面显示到屏幕上；也能做大量简单而相似的并行计算 显存容量、计算能力

另外还有电源（把交流电转换成各部件需要的直流电）、散热（风扇、散热片，防止 CPU 和显卡过热降频）和机箱。笔记本电脑把这些部件集成在一个很小的空间里，原理完全相同，只是更难更换和升级。

一个比喻：厨房

把电脑想象成一个厨房：

  • CPU 是厨师：真正干活的人。核心数是厨师的人数，频率是每个厨师的手速；
  • 内存是案板：正在处理的食材都摆在案板上，伸手就能拿到。案板越大，同时能处理的食材越多；
  • 硬盘是仓库：所有的食材和工具都存放在这里，容量大，但每次去取都要走一段路；
  • 显卡是一大群帮厨：每个人只会切菜这样简单的动作，但人非常多，切一大堆一样的菜时比厨师快得多。

一道菜做得慢，可能是厨师不够快（CPU），也可能是案板太小、食材要一趟趟从仓库搬（内存不够），还可能是仓库离厨房太远（硬盘太慢）。找出真正的瓶颈，才知道该升级什么。

二、CPU：核心、线程与频率

CPU 的性能主要由三个参数决定：

  • 频率（GHz）：每秒钟执行多少个时钟周期。3 GHz 就是每秒 30 亿个周期。频率决定了“一个核心”有多快；
  • 核心数：一个 CPU 里有几个能独立工作的处理单元。8 核的 CPU 可以同时运行 8 个任务；
  • 线程数：很多 CPU 用“超线程”技术让一个核心同时处理两个任务的指令流，所以常见“8 核 16 线程”。两个线程共用一个核心的计算资源，性能提升远小于一倍。

还有一个容易被忽略的参数：缓存。CPU 内部有几十 KB 到几十 MB 的高速存储，存放最近用过的数据。CPU 从缓存中取数据比从内存中取快几十倍，所以能把数据“挤在一起”连续处理的程序（比如 NumPy 对整个数组的运算），比在内存中东跳西跳的程序快得多。

核心多，不代表程序就快。一个程序要能利用多个核心，必须被写成并行的：

  • Python 的普通循环、大部分 pandas 操作只用一个核心（Python 系列第 17 篇讲了原因：全局解释器锁）；
  • NumPy 的矩阵运算、scikit-learn 的部分模型（n_jobs=-1）、DuckDB（SQL 系列第 06 篇）会自动使用多个核心；
  • 自助法、蒙特卡洛模拟、交叉验证这类“同样的事情做很多遍”的任务，很容易手动并行化（joblib、multiprocessing），这时核心数才真正派上用场。

所以，如果你的主要工作是单线程的 Python 代码，单个核心的速度（频率和架构）比核心数更重要；如果经常做大规模的模拟或者训练模型，核心数更重要。

三、内存：能同时处理多少数据

内存是 CPU 的工作台。程序运行时，代码和数据都要先从硬盘读进内存，CPU 才能处理。内存容量决定了你能同时处理多大的数据。

一个 DataFrame 占多少内存，可以直接估算：每个浮点数或整数占 8 个字节。100 万行、20 列的数值数据就是 字节，约 160 MB：

import numpy as np
import pandas as pd

df = pd.DataFrame(np.zeros((1_000_000, 20)), columns=[f"x{i}" for i in range(20)])
print(f"数值列：{df.memory_usage(deep=True).sum() / 1e6:.0f} MB")

df["code"] = [f"{i:06d}" for i in range(len(df))]        # 加一列 6 位的股票代码（文本）
print(f"加一列文本（{df['code'].dtype}）：{df.memory_usage(deep=True).sum() / 1e6:.0f} MB")
as_object = df.assign(code=df["code"].astype(object))           # pandas 2 及以前的默认存法
print(f"同一列存成 Python 对象：{as_object.memory_usage(deep=True).sum() / 1e6:.0f} MB")
数值列：160 MB
加一列文本（str）：174 MB
同一列存成 Python 对象：215 MB

文本列的内存取决于它怎样存储。pandas 3 默认用紧凑的字符串类型，100 万个 6 位代码只多占十几 MB；pandas 2 及以前的版本默认把每个字符串存成一个单独的 Python 对象，每个对象都有几十个字节的额外开销，同一列就要多占好几倍的内存。用旧版本的 pandas 时，把重复很多的文本列（行业、省份）转成 category 类型，或者把代码存成整数，可以省下很多内存。

实际需要的内存比数据本身大得多。读入 CSV、排序、合并、分组时，pandas 经常要创建数据的副本，一个经验法则是准备数据大小 5 到 10 倍的内存。16 GB 内存的电脑，用 pandas 舒适地处理的数据大约在 1–3 GB 以内。

内存不够时会发生什么？操作系统会把内存中暂时不用的部分写到硬盘上（虚拟内存、交换空间），需要时再读回来。硬盘比内存慢得多，程序会突然变得非常慢，硬盘指示灯一直亮着，整台电脑都变卡。数据再大一点，程序就会因为内存不足而崩溃（Python 中是 MemoryError，或者进程直接被系统终止）。

解决办法不一定是加内存：

  1. 只读需要的列（pd.read_csv(..., usecols=[...])）和需要的行；
  2. 用更省内存的类型（float32、category）；
  3. 用 Parquet 代替 CSV，用 DuckDB 在硬盘上直接汇总，只把汇总后的结果读进内存（SQL 系列第 06 篇）。

四、硬盘：容量与速度

硬盘有两种：

  • 机械硬盘（HDD）：数据存在高速旋转的磁盘上，由磁头移动到对应的位置读写。容量大、价格低，但要等磁盘转到正确的位置，读取分散的小文件特别慢；
  • 固态硬盘（SSD）：数据存在闪存芯片里，没有机械运动。连续读写速度是机械硬盘的几倍到几十倍，随机读写（读很多分散的小块数据）更是快几百倍。固态硬盘又按接口分为 SATA 和速度更快的 NVMe。

对日常使用来说，系统和程序装在固态硬盘上是体验差别最大的一项升级：开机、打开软件、读取数据都快得多。机械硬盘适合存放大量不常用的文件，比如备份和原始数据的归档。

速度的量级

图中是从 CPU 读取一小块数据所需的大致时间（对数坐标），每一层都比上一层慢一到几个数量级，容量则大几个数量级。这些数字随硬件变化，但量级的差距几十年来一直存在，这是理解程序性能最重要的一张图：

  • 数据在缓存和内存中时，CPU 几乎不用等待；
  • 每一次读硬盘，CPU 都要等待相当于几万到几百万次计算的时间；
  • 通过网络读取数据（爬虫、API、云端数据库）又比本地硬盘慢得多。

所以很多性能优化的本质是减少去慢的地方取数据的次数：一次读取一大块数据而不是很多次读取小块（Parquet 的列式存储），把常用的数据缓存在内存或本地（数据获取系列第 03 篇的缓存），批量提交数据库的写入（SQL 系列第 05 篇）。

数据安全：3-2-1 原则

硬盘会坏，而且往往没有预兆，固态硬盘也不例外。重要的数据遵循 3-2-1 原则：至少 3 份副本，存放在 2 种不同的介质上，其中 1 份在异地（比如云盘）。代码放在 Git 和 GitHub 上（实证研究工作流第 02 篇），本身就是一份异地备份。

五、显卡：显示与并行计算

显卡最初的用途是把画面显示到屏幕上。画面由几百万个像素组成，每个像素的计算都很简单而且彼此独立，所以显卡被设计成有成千上万个简单的计算核心，同时处理大量相似的计算。

这种结构恰好适合深度学习：神经网络的训练主要是大规模的矩阵乘法，可以拆成大量独立的小计算。同样的模型，在显卡上训练可能比在 CPU 上快几十倍。

两种显卡：

  • 集成显卡：集成在 CPU 里，和 CPU 共用内存。显示、看视频、日常办公完全够用；
  • 独立显卡：单独的一块卡，有自己的高速内存（显存）。玩游戏、做三维渲染、训练深度学习模型需要它。

对数据分析来说：

  • 回归、统计检验、pandas 数据处理、树模型（大多数情况下）不需要独立显卡；
  • 训练神经网络、使用大型预训练模型时，显卡的显存容量往往比计算速度更关键：模型和一批数据放不进显存，就根本无法运行；
  • 主流的深度学习框架对 NVIDIA 显卡（CUDA）的支持最完善；苹果电脑的芯片有自己的加速方案，也能运行很多框架。

偶尔需要显卡时，用云端的计算资源（比如 Google Colab 或学校的计算集群）往往比买一块高端显卡更划算。

六、查看自己电脑的配置

几行 Python 就能查看主要的配置（输出因电脑而异）：

import os
import platform
import shutil

print("操作系统：", platform.system(), platform.release())
print("处理器：  ", platform.processor() or platform.machine())
print("逻辑核心：", os.cpu_count())
total, used, free = shutil.disk_usage("/")
print(f"硬盘：     共 {total / 1e9:.0f} GB，剩余 {free / 1e9:.0f} GB")
操作系统： Linux 6.18.44-fc-v819
处理器：   x86_64
逻辑核心： 4
硬盘：     共 271 GB，剩余 28 GB

os.cpu_count() 返回的是逻辑核心数（线程数）。查看内存容量需要第三方库 psutil（pip install psutil，然后 psutil.virtual_memory().total）。

也可以用操作系统自带的工具：Windows 的“任务管理器 → 性能”，macOS 的“关于本机”和“活动监视器”，Linux 的 lscpu、free -h、df -h 命令。程序运行慢的时候，打开任务管理器（活动监视器）看一看：

现象 瓶颈 可以怎么做
一个 CPU 核心 100%，其他核心空闲 程序是单线程的 向量化（NumPy/pandas 代替循环）；把独立的任务并行化
所有 CPU 核心都接近 100% 计算量确实很大 更快的算法；更多核心；放到服务器上运行
内存接近用满，硬盘读写很忙 内存不够，在使用虚拟内存 少读数据、用更省内存的类型、DuckDB；加内存
CPU 和内存都不忙，程序却很慢 在等硬盘或网络 换固态硬盘；缓存；减少网络请求的次数

七、按用途选电脑

不推荐具体型号（每年都在变），只说按用途应该优先考虑什么：

主要用途 优先考虑 不必追求
写论文、Excel、Stata 处理小数据 固态硬盘；舒适的屏幕和键盘 高端 CPU、独立显卡
用 Python/R 处理中等规模的数据（几 GB） 内存（16 GB 起，32 GB 更从容）；固态硬盘 独立显卡
大规模模拟、自助法、交叉验证 CPU 核心数；内存 独立显卡
几十 GB 以上的数据 大容量 NVMe 固态硬盘；内存；配合 DuckDB、Parquet 一味加内存（数据总会比内存大）
训练深度学习模型 显存大的独立显卡；或者直接用云端/学校的 GPU —

两个常被忽略的建议：

  • 内存和硬盘宁可一步到位：很多笔记本电脑的内存焊死在主板上，买了之后无法升级；
  • 电脑不是越贵越好：真正大规模的计算任务，学校的服务器、计算集群和云端资源比任何个人电脑都强，而且只在需要时付费。

小结

  • CPU 执行指令，内存存放正在处理的数据，硬盘长期保存文件，显卡负责显示和大规模并行计算，它们都通过主板连接。
  • 核心多不代表程序快：单线程的程序只用一个核心；并行化的程序才能利用多个核心。
  • 内存容量决定能同时处理多大的数据；pandas 大约需要数据大小 5 到 10 倍的内存；内存不够时程序会突然变得极慢或崩溃。
  • 缓存、内存、固态硬盘、机械硬盘、网络的访问速度相差几个数量级，减少去慢的地方取数据的次数是性能优化的核心。
  • 独立显卡主要用于游戏、渲染和深度学习，普通的统计分析不需要。
  • 按用途而不是按型号选电脑；重要数据遵循 3-2-1 备份原则。

练习

  1. 用第六节的代码和操作系统自带的工具，查出你的电脑有几个核心、多大内存、硬盘是固态还是机械的。
  2. 读入一个你常用的 CSV 文件，用 df.memory_usage(deep=True) 看看哪些列最占内存。把文本列转成 category 类型后，内存减少了多少？
  3. 写一个做 1000 次自助法的程序，分别用普通循环和 joblib.Parallel 运行，观察任务管理器中 CPU 的使用情况，并比较运行时间。
